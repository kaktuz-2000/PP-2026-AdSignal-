# AdSignal

AdSignal — прототип прогнозно-аналитической системы: оценивает CTR рекламы по сегментам и категориям, сравнивает модели, объясняет прогнозы и ранжирует объявления по интересам аудитории.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app.py
```

При первом запуске будут созданы синтетические источники и SQLite-хранилище. Откройте адрес Streamlit, обычно `http://localhost:8501`. Проверить основной пайплайн:

```bash
python -m unittest discover -s tests -v
```

Чтобы повторно рассчитать прогноз из терминала:

```bash
python - <<'PY'
from src.ad_recommender import read_sources, train_models

events, ads, loads = read_sources()
metrics, forecasts, active_model = train_models(events)
print(metrics.to_string(index=False))
print("Активная модель:", active_model)
print(forecasts.head().to_string(index=False))
PY
```

`src/ad_recommender.py` содержит генерацию и проверку источников, идемпотентную загрузку, построение признаков, обучение, оценку, объяснение, мониторинг и реестр. Ежедневная витрина сохраняется в SQLite вместе с исходными событиями, каталогом, журналами, экспериментами, снимками датасетов и версиями моделей. `app.py` предоставляет интерфейс загрузки данных и просмотра аналитики. SQLite хранится в `data/processed/ads.sqlite3`, исходные CSV — в `data/raw/`.

## Источники и качество данных

Можно использовать синтетические данные или загрузить собственные CSV в боковой панели.

Журнал событий должен содержать:

```text
event_id,timestamp,user_id,segment,ad_id,category,viewed,clicked,liked,reposted
```

Каталог объявлений:

```text
ad_id,category,title,advertiser
```

`event_id` и `ad_id` должны быть уникальны; временные метки — корректны; показатели взаимодействий — `0` или `1`; клик не может быть без показа, а лайк/репост — без клика. Категория объявления в событиях должна совпадать с каталогом. Повторный запуск загрузки не дублирует уже известные `event_id`. Проверки и загрузки записываются в SQLite.


## Признаки и модели

Целевая переменная — CTR следующего календарного дня для пары «сегмент × категория». Используются CTR предыдущего дня, средний CTR за предыдущие семь дней, показы предыдущего дня, сегмент, категория и календарные признаки. Пропущенные дни создаются в ежедневной сетке; лаги заполняются только прошлыми значениями. Данные разделяются по времени: ранний train, следующий validation для выбора модели и более поздний holdout для итоговой проверки.

Сравниваются:

1. Наивная модель — CTR последнего наблюдения.
2. Линейная регрессия.
3. Случайный лес с ограниченным перебором конфигураций.

Отбор признаков выполняется только на train: случайный лес ранжирует закодированные признаки, затем проверяются полный набор и минимальный набор, покрывающий 90% суммарной важности. Варианты сравниваются по validation; holdout остается нетронутым до итоговой оценки. Для сравнения выводятся MAE и RMSE на holdout; средний прогноз дополнительно переводится в ожидаемые клики на 1000 показов. Настройки находятся в `config.toml`: `demo.seed`, `demo.days`, `model.search_budget` (от 1 до 4 конфигураций случайного леса) и `model.promotion_threshold`.

Важность признаков исследуется двумя способами: permutation importance и взаимная информация, с сопоставлением validation и holdout периодов. Для выбранного прогноза на произвольную доступную дату интерфейс показывает изменение CTR при замене каждого признака на типичное значение и график зависимости прогноза от выбранного признака. Эти эффекты независимы и не являются аддитивным объяснением причинности.

## Мониторинг и версии

Эксперименты сохраняют конфигурацию, seed, метрики, контрольную сумму данных и сжатый снимок событий. Эксперимент можно выбрать в интерфейсе и воспроизвести на исходном снимке.

Мониторинг записывает PSI входных признаков и MAE последнего окна. Правило рекомендации переобучения: PSI не ниже `0.20` либо MAE последнего окна больше holdout MAE активной версии более чем на `25%`. Поиск ограничен бюджетом из конфигурации. Новая версия становится активной, только если validation MAE улучшилась минимум на настроенный процент; иначе сохраняется текущая. Реестр хранит артефакты и параметры моделей, версии можно активировать вручную или откатить на предыдущую.
