# Ad Signals

Прототип прогнозно-аналитической системы для подбора рекламы по истории взаимодействий. Система прогнозирует CTR на следующий день по сегменту аудитории и категории объявления, сравнивает три модели и ранжирует объявления по прогнозу и интересам пользователя.

Данные полностью синтетические: персональные данные и реальные профили не используются.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app.py
```

При первом запуске создаются CSV-источники и SQLite-хранилище. Параметры демонстрационных данных задаются в `config.toml`. Для повторной проверки пайплайна:

```bash
python -m unittest discover -s tests
```

## Архитектура

1. `data/raw/interaction_events.csv` — слабоструктурированный журнал событий: просмотры, клики, лайки и репосты.
2. `data/raw/ad_catalog.csv` — отдельный источник с объявлениями и категориями.
3. `src/ad_recommender.py` выполняет загрузку с дедупликацией по `event_id`, хранит события, каталог и журнал загрузок в SQLite, строит признаки и обучает модели.
4. `app.py` показывает историю CTR, прогноз, сравнение моделей и ранжированную выдачу для выбранного синтетического пользователя.

Схема потока: CSV-журнал + CSV-каталог → SQLite → ежедневные признаки → валидация и обучение → прогноз CTR → рекомендации и дашборд.

## Постановка задачи

Целевая переменная — CTR следующего дня для пары «сегмент × категория объявления». Признаки включают категорию и сегмент, CTR предыдущего дня, средний CTR за предыдущие семь дней, число показов предыдущего дня и календарные признаки прогнозного дня. Лаги и скользящее среднее рассчитываются только по прошлым наблюдениям; проверочная часть следует позже обучающей.

Модели сравниваются на одном временном holdout: наивный прогноз (CTR предыдущего дня), линейная регрессия и случайный лес. Используются MAE и RMSE; CTR также переводится в ожидаемое число кликов на 1000 показов. Для выдачи прогноз CTR взвешивается интересом к категории, рассчитанным из истории просмотров, кликов, лайков и репостов.

## Границы прототипа

Генератор данных имитирует события для демонстрации полного цикла, а не реальный рекламный трафик. Перед подключением настоящего источника нужно отдельно согласовать его доступность и правовое основание обработки, исключить персональные данные, описать обновление источника и повторно проверить временную валидацию. Мониторинг дрейфа и автоматическое переобучение оставлены как возможное расширение проекта.
